# Node 8：产品形态与分发渠道选择

**目标**：判断在哪种产品形态下交付，用户获取成本最低、体验最完整、平台限制最少。

---

## 产品形态选项矩阵

| 形态 | 适合场景 | 平台依赖 | 冷启动难度 |
|------|----------|----------|-----------|
| 独立 App（iOS/Android） | 高频使用、需要通知推送、离线能力 | 高（App Store/Google Play 审核） | 高 |
| 微信小程序 | 社交裂变、低频尝鲜、中国市场 | 中（微信政策） | 低 |
| H5 / Web App | 快速验证、跨平台、无需安装 | 低 | 最低 |
| 微信插件/企业微信 | B端、工作场景、内部工具 | 高（腾讯生态） | 中 |
| SaaS 后台 | B端订阅、批量处理、API服务 | 低 | 中 |
| 抖音/快手小程序 | 短视频场景、娱乐/内容消费 | 高（字节/快手政策） | 中 |

---

## 形态选择决策框架

**问题 1：用户在哪里？**
- 用户主要在微信生态 → 优先小程序
- 用户是重度内容消费者 → 优先抖音/短视频平台
- 用户需要专业工具 → 独立 App 或 Web

**问题 2：产品需要什么权限/能力？**
- 需要相机/麦克风/本地存储 → 独立 App（权限最完整）
- 需要社交分享裂变 → 微信小程序
- 需要快速迭代验证 → H5/Web（无需审核）

**问题 3：平台政策风险有多高？**
- 检索：`App Store [产品类别] rejected review guideline`
- 检索：`微信小程序 [功能] 违规 下架`
- 检索：`抖音小程序 [功能] 审核拒绝`

**问题 4：MVP 阶段用什么形态验证？**
- 建议：MVP 优先 H5 或小程序（快、低成本）
- 验证成功后再投入独立 App 开发

## 渠道-形态匹配矩阵

⚠️ 需要用户提供以下信息（如无法提供，跳过本节，输出结果中标注「信息不足」）：

- 你的目标用户主要在哪个平台活跃？
- 现有的流量入口或资源（公众号粉丝、私域用户、合作渠道）？
- 是否有平台合作关系或内部资源倾斜？

**如果用户未提供，向其发出引导提问：**
> "你的目标用户平时主要在哪个 App 上？你们公司或团队目前有没有现成的流量资源，比如公众号、私域群、或者平台合作？"

| 分发渠道 | 匹配形态 | 所需资源 |
|----------|----------|----------|
| 微信私域/公众号 | 小程序 / H5 | 已有粉丝基础 |
| 抖音/视频号内容运营 | 抖音小程序 / 独立 App | 内容生产能力 |
| ASO 自然搜索 | 独立 App | 长期投入 |
| B端销售/企业采购 | SaaS / 企业微信 | 销售团队 |
| KOL/KOC 种草 | 小程序 / H5 | 预算或关系资源 |

---

## 平台政策风险评级（与 Node 7 联动）

| 平台 | 主要审核红线 |
|------|------------|
| App Store | 隐私数据、未成年保护、订阅透明度、AI生成内容标注 |
| 微信小程序 | 不得绕过微信支付、内容合规、诱导分享 |
| 抖音小程序 | 内容导流限制、电商资质要求 |
| Google Play | 数据安全表单、敏感权限声明 |

---

## 产出
产品形态推荐（首选 + 备选）+ 分发渠道优先级 + 平台政策风险提示
→ 输入最终报告「放在哪里才是最合适的产品形态」章节

> 若本节信息不足：输出「产品形态建议基于公开信息推断，缺少团队现有资源和用户平台分布数据，建议补充后重新评估」
