# Node 6：商业化可行性与业务加成评估

**目标**：判断产品在财务上是否自洽，或对现有业务有何战略价值。

## 商业模式选择（基于 Node 3 需求类型）
- 止痛药 + 高频 + 强转换成本 → **订阅制**（最优）
- 周期性需求 + 单次消费意图 → **按次付费**
- 高 DAU 但低付费意愿 → **广告/增值服务**
- 平台型双边 → **佣金/生态**

## 单位经济学粗估
- **LTV**（用户生命周期价值）= 月均付费 × 平均留存月数
- **CAC**（获客成本）= 参考同赛道数据（WebSearch `[赛道] CAC 获客成本 行业均值`）
- **健康标准**：LTV/CAC > 3，回收期 < 12个月

## 对现有业务的加成（平台内创新产品适用）

| 加成类型 | 评估问题 |
|----------|----------|
| 流量加成 | 能为母平台引入多少新用户？ |
| 时长加成 | 用户在母平台停留时间增加吗？ |
| 生态加成 | 是否产生更多 UGC 或内容循环？ |
| 防御加成 | 是否防止核心用户流失到竞品？ |

## 信息搜索
- WebSearch `[竞品] 商业模式 收入 定价`
- WebSearch `[英文竞品] business model revenue pricing`

## 产出
商业化可行性报告（商业模式 + LTV/CAC 估算 + 业务加成假设）→ 输入 Node 7 财务风险
