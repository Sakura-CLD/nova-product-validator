# Node 2：竞品与失败案例归因

**目标**：精确回答「为什么他们失败了，为什么我们不会因同样原因失败」。

## 信息搜索
- WebSearch `[竞品名] 为什么失败 倒闭原因 36氪 虎嗅`
- WebSearch `[英文竞品] failed shutdown reason techcrunch`
- WebSearch `[赛道] 失败案例分析`
- WebSearch `[赛道关键词] 成功案例 增长 a16z`

## 失败类型归因（对每个竞品打标签）

| 类型 | 定义 | 识别方式 |
|------|------|----------|
| **结构性失败** | 方向本身需求不成立 | 所有同类都失败，用户根本不付钱 |
| **执行性失败** | 方向对但做法错了 | 部分同类成功，该产品有特有问题 |
| **时机性失败** | 方向和做法都对，但时机太早 | 技术/用户心智当时不成熟 |

## 关键动作
用 Node 1 的四层需求框架重新解构每个失败竞品，找出它的本质定义哪里错了。

## 产出
失败案例归因矩阵（本质定义 + 失败类型 + 我们与它的根本区别）→ 输入 Node 5
