# Node 5：差异化与护城河体系构建

**目标**：论证「为什么我们能赢」，而不只是「为什么对手输了」。

## 7 Powers 护城河识别（找出2-3种叠加）

| 护城河类型 | 定义 | 识别问题 |
|------------|------|----------|
| 网络效应 | 用户越多，产品越有价值 | 用户A加入是否让用户B受益？ |
| 转换成本 | 迁移到竞品代价极高 | 用户积累了什么难以带走的资产？ |
| 规模经济 | 规模越大，单位成本越低 | 边际成本是否随规模下降？ |
| 反向定位 | 我们的模式让大厂不敢跟进 | 大厂复制我们是否伤害其现有业务？ |
| 品牌 | 用户对品牌的信任溢价 | 用户是否因为「是我们」而选择？ |
| 独特资源 | 独家占据关键资源 | 是否有竞争对手无法复制的数据/内容？ |
| 流程优势 | 内部积累的效率优势 | 执行流程是否难以被外部复制？ |

## 四维差异化框架

| 维度 | 问题 | 填写 |
|------|------|------|
| **Who（用户层）** | 我们的目标用户和竞品是本质不同的人吗？ | 两类用户的核心动机差异 |
| **What（产品本质层）** | 我们卖的和竞品卖的本质上是不同的东西吗？ | 我们卖什么？竞品卖什么？ |
| **Against Whom（竞争边界层）** | 我们真正的竞争对手是谁？ | 重申 Node 1 的竞争对手重定义 |
| **Scale（供给天花板层）** | 我们的产品边界和竞品差距多大？ | 我们的上限 vs 竞品的上限 |

## 护城河建立时间线
- **Day 1**：没有护城河时靠什么竞争？（通常是「体验最好」）
- **第6个月**：哪个护城河开始生效？
- **第2-3年**：哪个护城河形成难以撼动的壁垒？

## 技术可行性与成本障碍评估

⚠️ 需要用户提供以下信息（如无法提供，跳过本节，输出结果中标注「信息不足」）：

- 团队是否具备核心技术能力（自研 / API调用 / 外包）？
- 预估 MVP 建设周期和预算范围？
- 是否依赖第三方平台/模型/数据源？

**如果用户未提供，向其发出引导提问：**
> "您的团队目前的技术构成是怎样的？核心功能打算自研还是调用第三方 API？有没有大致的启动预算范围？"

**技术可行性矩阵：**
| 维度 | 评估问题 | 风险等级 |
|------|----------|---------|
| 核心技术依赖 | 关键能力是自研/API/采购？供应商是否稳定？ | 高依赖=高风险 |
| 数据壁垒 | 需要什么数据？怎么获取？有没有冷启动问题？ | 无数据=无法启动 |
| 算力/成本结构 | 规模增长后边际成本如何变化？ | 边际成本不降=商业模式有问题 |
| 替代方案成本 | 自研 vs API vs 外包的成本和时间对比 | — |

**MVP 成本下限估算（需用户提供或公开数据推算）：**
- 建设成本 = 人力成本 + 第三方 API/工具费用 + 基础设施
- 6个月运营成本下限 = 获客成本（CAC × 目标用户数）+ 运营成本

> 若本节信息不足：输出「技术/成本可行性：信息不足（需要团队构成、技术路线、预算范围才能完成此部分分析）」

护城河体系（2-3个叠加护城河 + 四维差异化 + 时间线）+ 技术可行性结论 + 成本结构估算 → 整个分析的核心对外输出
