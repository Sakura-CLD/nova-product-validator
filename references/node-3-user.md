# Node 3：目标用户需求真伪验证

**目标**：验证需求是「止痛药」还是「维生素」，用户是否真的会付钱。

## 信息搜索（行为数据优先于意见数据）
- WebSearch `[关键词] 小红书 种草 收藏`（收藏量高 = 真实需求）
- WebSearch `[竞品] 用户评价 值不值得买`
- WebSearch `[英文竞品] reddit review worth paying`

## 止痛药 vs 维生素判断

| 维度 | 止痛药（值得做）| 维生素（谨慎）|
|------|----------------|--------------|
| 没有这个怎么办？ | 只能用低效替代方案 | 无所谓，凑合 |
| 用户现在付钱给谁？ | 在为不完美的同类付钱 | 没有付钱 |
| 需求频率 | 高频（每周/每天）| 低频或一次性 |
| 情绪词 | 「太烦了」「终于」| 「挺好的」 |

## 用户访谈问题模板（提供给用户去做访谈）
1. 你上一次遇到这个问题是什么时候？
2. 当时你是怎么解决的？
3. 你对那个解决方案哪里不满意？
4. 如果有完美方案，你觉得值多少钱一个月？

## 用户假设校验（Mom Test）

> 你设想的用户，是真实用户吗？

⚠️ 需要用户提供以下信息（如无法提供，跳过本节，输出结果中标注「信息不足」）：

- 已有的用户访谈记录或用户反馈数据？
- 产品目前的种子用户来自哪里（内部员工/定向邀请/自然流量）？
- 是否做过任何形式的付费验证？

**如果用户未提供，向其发出引导提问：**
> "您目前有没有和任何潜在用户聊过？哪怕3-5个人也算。如果有，他们在用什么替代方案解决这个问题？"

**Mom Test 核心原则（不问意愿，只问行为）：**
- ✅ 问：「上一次遇到这个问题是什么时候？当时怎么解决的？」
- ✅ 问：「你现在为这类需求花钱了吗？花在哪里？」
- ❌ 不问：「你会用我们的产品吗？」（用户会撒善意的谎）

**用户假设核查清单：**
| 假设 | 需要验证的问题 |
|------|--------------|
| 用户年龄/圈层假设 | 真实付费用户和设想的是同一类人吗？ |
| 使用场景假设 | 用户在什么具体场景下触发这个需求？ |
| 付费动机假设 | 用户付钱是为了省时/炫耀/解决痛点？ |
| 频率假设 | 需求是每天/每周/偶发？ |

## 产出
需求真伪评估（止痛药/维生素 + 付费意愿估算 + 用户 Persona + 用户假设校验结论）→ 输入 Node 4 市场规模、Node 6 商业模式
> 若本节信息不足：输出「用户假设校验：信息不足（需要用户访谈记录或种子用户反馈才能完成此部分分析）」
