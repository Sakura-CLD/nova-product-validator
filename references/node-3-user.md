# Node 3：目标用户需求真伪验证

**目标**：验证需求是「止痛药」还是「维生素」，用户是否真的会付钱。

## 信息搜索（行为数据优先于意见数据）
- WebSearch `[关键词] 小红书 种草 收藏`（收藏量高 = 真实需求）
- WebSearch `[竞品] 用户评价 值不值得买`
- WebSearch `[英文竞品] reddit review worth paying`

## 止痛药 vs 维生素判断

| 维度 | 止痛药（值得做）| 维生素（谨慎）|
|------|----------------|--------------|
| 没有这个怎么办？ | 只能用低效替代方案 | 无所谓，凑合 |
| 用户现在付钱给谁？ | 在为不完美的同类付钱 | 没有付钱 |
| 需求频率 | 高频（每周/每天）| 低频或一次性 |
| 情绪词 | 「太烦了」「终于」| 「挺好的」 |

## 用户访谈问题模板（提供给用户去做访谈）
1. 你上一次遇到这个问题是什么时候？
2. 当时你是怎么解决的？
3. 你对那个解决方案哪里不满意？
4. 如果有完美方案，你觉得值多少钱一个月？

## 产出
需求真伪评估（止痛药/维生素 + 付费意愿估算 + 用户 Persona）→ 输入 Node 4 市场规模、Node 6 商业模式
